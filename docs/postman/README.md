# مجموعة Postman — GovMind

مجموعة تغطي **مسارات الـBackend الموجودة فعلًا في OpenAPI**، بلا أي مسار
مُخترَع: صحة الخدمة، والمصادقة، والمحادثات والرسائل، والملفات، والجهة
والموظفين، والاشتراك وإعدادات المودل، وسجل التدقيق، وتجهيز جهة جديدة، وحالات
الخطأ.

| الملف                                    | ما هو                          |
| ---------------------------------------- | ------------------------------ |
| `GovAgent.postman_collection.json`       | المجموعة — ٩ مجلدات، ٤٢ طلبًا  |
| `GovAgent.postman_environment.json`      | بيئة محلية بمتغيّرات فارغة     |

---

## ١. التشغيل

شغّل الـBackend أولًا:

```bash
cd backend && .venv/Scripts/python -m uvicorn app.main:app --reload --port 8000
```

(على لينكس أو ماك استبدل `.venv/Scripts/` بـ`.venv/bin/`.)

تأكد أنه يعمل: <http://localhost:8000/health>

## ٢. الاستيراد

1. افتح Postman ← **Import**.
2. اسحب الملفين معًا: المجموعة والبيئة.
3. اختر بيئة **GovMind — محلي** من قائمة البيئات أعلى اليمين.

## ٣. كلمة مرور التطوير

**المجموعة والبيئة لا تحتويان أي كلمة مرور**؛ المتغيّرات فارغة عمدًا حتى لا
يُخزَّن سرٌّ في المستودع ولو كان تجريبيًا.

كلمة مرور مستخدمي التطوير في مخزن الذاكرة هي قيمة `DEV_SEED_PASSWORD` في
`.env`، وافتراضها:

```
GovAgent@2026
```

> هذه كلمة مرور **تطوير محلي فقط**، لحسابات خيالية على نطاقات `.test` في مخزن
> غير دائم يفرغ عند إعادة التشغيل. **لا تُستخدم في أي نشر حقيقي**، ولا
> تُوضع في أي ملف داخل المستودع غير هذا التوثيق.

الصقها مرة واحدة في متغيّر البيئة `dev_password`:

**Environments ← GovMind — محلي ← `dev_password` ← Current value**

ضعها في **Current value** لا في **Initial value**: القيمة الأولية هي ما
يُصدَّر ويُشارَك، والحالية تبقى على جهازك وحدك.

### متغيّرات فارغة أخرى

| المتغيّر             | متى تملؤه                                                |
| -------------------- | -------------------------------------------------------- |
| `new_user_password`  | قبل «إضافة موظف» و«تجهيز جهة» — أي قيمة قوية تختارها.     |
| `provisioning_key`   | قبل مجلدَي التجهيز وتعديل الاشتراك — قيمة `PROVISIONING_KEY` على سيرفرك. |

`PROVISIONING_KEY` **إلزامي في كل البيئات**؛ تركه فارغًا يعطّل المسار ويعيد
**503**، ولا يجعله مفتوحًا. التطوير المحلي لا يحتاجه: مخزن الذاكرة مزروع
بجهات جاهزة.

## ٤. الترتيب

شغّل **مجلد «٢ · المصادقة» أولًا**:

- **تسجيل الدخول** يحفظ `access_token` في `{{token}}` تلقائيًا، ومعه
  `{{organization_id}}` و `{{user_id}}`.
- **تسجيل دخول المسؤول** يحفظ `{{admin_token}}` — تحتاجه مجلدات الموظفين
  والاشتراك وسجل التدقيق، لأن تلك المسارات لدور `admin` وحده.

بعدها تعمل بقية المجلدات بلا نسخ ولصق. باقي المتغيّرات
(`{{conversation_id}}` و `{{file_id}}` و `{{created_user_id}}` …) تملؤها
سكربتات الاختبار عند تشغيل الطلبات بالترتيب.

المصادقة على مستوى المجموعة هي `Bearer {{token}}`، وتتجاوزها الطلبات التي
لا تحتاج رمزًا (`/health`، وتسجيل الدخول، ومسارات مفتاح التجهيز) أو التي
تحتاج رمز المسؤول.

## ٥. مجلد التشغيل (Working Directory) — مهم

طلب **«رفع ملف»** يرفع ملفًا من داخل المستودع بمسار **نسبي**:

```
mock-data/files/لائحة-الإجازات.txt
```

نسبي لا مطلق، حتى تعمل المجموعة على أي جهاز بعد `git clone` مباشرة بلا تعديل
ولا مسار يخص جهازًا بعينه. ولأنه نسبي، **يجب أن يكون مجلد التشغيل هو جذر
المستودع**.

### في newman

شغّل الأمر **من جذر المستودع**:

```bash
npx newman run docs/postman/GovAgent.postman_collection.json \
  -e docs/postman/GovAgent.postman_environment.json \
  --env-var "dev_password=GovAgent@2026" \
  --env-var "new_user_password=Postman@2026"
```

أو من أي مجلد آخر مع تحديد الجذر صراحةً بـ`--working-dir`:

```bash
npx newman run GovAgent.postman_collection.json \
  -e GovAgent.postman_environment.json \
  --working-dir ../.. \
  --env-var "dev_password=GovAgent@2026"
```

تشغيله من مجلد خاطئ يعطي خطأً صريحًا يذكر الحل:

```
Form param `file`, file load error: "mock-data/files/لائحة-الإجازات.txt", no such file
```

### في Postman

**Settings ← General ← Working directory** ← اختر **جذر المستودع**
(`govagent-repo`)، ثم **Runner** ← اختر المجموعة والبيئة ← **Run**.

### عيّنات الملفات

الملف المستخدم في الطلب هو `لائحة-الإجازات.txt`، ويستشهد به الطلب التالي له
في حقل `sources`. بقية العيّنات في
[`mock-data/files/`](../../mock-data/files/) لتجربتها يدويًا:

| الملف                              | المتوقع                          |
| ---------------------------------- | -------------------------------- |
| `لائحة-الإجازات.txt`               | **201** وحالته `processed`       |
| `دليل-الخدمات-الإلكترونية.docx`    | **201** وحالته `processed`       |
| `نموذج-طلب-إجازة.pdf`              | **201** وحالته `processed`       |
| `جدول-الميزانية.xlsx`              | **415** — صيغة غير مدعومة        |

## ٦. النتيجة المتوقعة

من جذر المستودع، وبالـBackend يعمل، تنجح المجموعة كاملة بلا أي تدخل يدوي:

```
requests    42 / 0 failed
assertions  97 / 0 failed
```

طلبان يحتاجان `{{provisioning_key}}`؛ بدونه يعيدان **503** وهو سلوك مقصود لا
عطل، واختباراتهما تقبل الحالتين.

## ٧. ما تتحقق منه سكربتات الاختبار

كل طلب فيه اختبارات لا تكتفي برمز الحالة:

- **لا تسريب:** ردود الحساب والموظفين لا تحمل `password_hash`، ورد الملف لا
  يحمل `storage_path`، ورد التحقق لا يعيد القيمة التي أرسلها المستخدم.
- **عزل الجهات:** موظفو القائمة كلهم من جهة واحدة، وجهة أخرى تعيد **404 لا
  403** — «ممنوع» تؤكد أن السجل موجود، وهذه معلومة عن جهة أخرى.
- **شكل الخطأ الموحّد:** `{ detail, status, code, errors }` و`detail` نصٌّ
  عربي دائمًا، حتى في أخطاء التحقق.
- **ترتيب الرسائل:** من الأقدم إلى الأحدث.
- **رفض السياق الملفّق:** إرسال `history` مع رمز دخول يُرفض بـ**422**.
- **انتهاء الاشتراك:** الدخول بحساب من الجهة الثالثة يعيد **403** برسالة
  تذكر تاريخ `2025-06-30`.

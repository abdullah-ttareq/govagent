## قواعد إرشادية فقط

- التوزيع في هذه الملفات **اقتراح تنظيمي**، وليس ملكية.
- **أي عضو يستطيع تعديل أي ملف يحتاجه** لإنجاز مهمته.
- **قائد الفريق يستطيع نقل أي مهمة** بين الأعضاء في أي وقت.
- لا توجد ملكية إجبارية لأي مجلد، ولا موافقات، ولا قيود آلية.
- لا Issues ولا Branch Protection ولا CODEOWNERS ولا Git Hooks ولا CI Gates.
- **الاختبارات للتأكد والتسجيل فقط.** فشل اختبار **لا يمنع حفظ العمل**. سجّل
  الفشل كما ظهر، وأبلغ قائد الفريق، واستمر.
- Claude لا ينفّذ `commit` أو `push` أو `merge`، ولا ينشئ أو يحذف فروعًا.

## نقطة البداية الجاهزة

مجلد [`extension/`](../extension/) فيه **Starter يعمل الآن**: Manifest V3،
ونافذة عربية RTL، وحقل رسالة وزر إرسال، وعرض رد الـBackend، وحالتا Loading و
Error، وإعداد قابل للتغيير لـAPI Base URL، و`README` يشرح Load unpacked.

قيود ثابتة للإضافة:

- **HTML و CSS و JavaScript مباشر فقط.** لا React ولا أي Build System.
- **لا Content Scripts** ولا أي صلاحية لقراءة صفحات المستخدم.

# P4-01 — تطوير إضافة المتصفح

- **الحالة:** Not Started
- **تعتمد على:** الـStarter الموجود في `extension/`
- **الملفات المتوقعة:** `extension/`

## ما تشمله

1. **ربط الإضافة بالمصادقة:** تسجيل دخول من داخل النافذة، وحفظ الـToken في
   `chrome.storage.local`، وإرساله مع كل طلب، وتسجيل خروج.
2. **سجل المحادثة داخل النافذة:** عرض الرسائل السابقة بدل رد واحد فقط،
   وتمرير تلقائي إلى الأسفل، وزر «محادثة جديدة».
3. الاحتفاظ بالمحادثة الأخيرة بعد إغلاق النافذة وإعادة فتحها.
4. **تحسين حالات الخطأ:** جلسة منتهية، اشتراك منتهٍ، سيرفر متوقف، إذن نطاق
   غير ممنوح — لكل حالة رسالة عربية واضحة وإجراء مقترح.
5. صقل النافذة: أيقونة الإضافة، وارتفاع مناسب بلا قفزات، ودعم لوحة المفاتيح.

## شرط الإنجاز

- الإضافة تعمل بعد Load unpacked وترسل وتستقبل من الـBackend.
- **صفر Content Scripts وصفر صلاحيات قراءة صفحات** في `manifest.json`.
- تبديل رابط السيرفر ما زال يعمل.

```
اقرأ docs/PERSON_4.md و extension/README.md.
نفّذ المهمة P4-01. تأكد من أنك داخل C:\Users\abdul\govagent-repo عبر
git rev-parse --show-toplevel قبل أي تعديل.
افحص مجلد extension/ كاملًا قبل التعديل. طوّر الـStarter الموجود ولا تعِد
إنشاءه.
لا تعمل Commit أو Push أو Merge، ولا تنشئ فروعًا أو Issues.

قيود ثابتة: HTML و CSS و JavaScript مباشر فقط. لا React ولا Build System.
لا Content Scripts ولا أي صلاحية لقراءة صفحات المستخدم.

المطلوب:
1. أضف تسجيل دخول من داخل النافذة: احفظ الـToken في chrome.storage.local،
   وأرسله مع كل طلب، وأضف تسجيل خروج.
2. اعرض سجل المحادثة داخل النافذة بدل رد واحد فقط، مع تمرير تلقائي إلى
   الأسفل وزر «محادثة جديدة».
3. احتفظ بالمحادثة الأخيرة بعد إغلاق النافذة وإعادة فتحها.
4. حسّن رسائل الخطأ: جلسة منتهية، اشتراك منتهٍ، سيرفر متوقف، إذن نطاق غير
   ممنوح — لكل حالة رسالة عربية واضحة وإجراء مقترح.
5. اصقل النافذة: أيقونة للإضافة، ارتفاع مستقر بلا قفزات، ودعم لوحة المفاتيح.

جرّب فعليًا عبر Load unpacked مع تشغيل الـBackend، واذكر ما رأيته.
في النهاية اذكر الملفات المعدّلة ونتيجة التجربة كما ظهرت فعلًا.

# P4-02 — البيانات التجريبية ومجموعة Postman

- **الحالة:** Not Started
- **تعتمد على:** لا شيء (تتحسّن بعد عمل PERSON_2)
- **الملفات المتوقعة:** `mock-data/` · `docs/`

## ما تشمله

1. **بيانات جهات ومستخدمين تجريبية:** جهتان على الأقل، ولكل جهة مسؤول وعدة
   موظفين، بأدوار واشتراكات مختلفة (واحد ساري وواحد منتهٍ).
2. **بيانات محادثات وملفات تجريبية:** محادثات بأطوال مختلفة، ورسائل عربية
   واقعية، وملفات بأسماء وأنواع مختلفة.
3. **لا أسرار حقيقية إطلاقًا:** لا كلمات مرور حقيقية ولا بيانات حكومية
   حقيقية. كلمات المرور التجريبية مذكورة كنص واضح **في التوثيق فقط**، لا في
   قاعدة البيانات.
4. **مجموعة Postman** تغطي كل المسارات: صحة الخدمة، الدخول، المحادثات،
   الرسائل، رفع الملفات، لوحة المسؤول.
5. متغيرات بيئة في المجموعة (`base_url` و `token`) بحيث يعمل الجميع بلا تعديل
   يدوي، مع خطوة دخول تملأ الـToken تلقائيًا.

## شرط الإنجاز

- عضو جديد يستورد المجموعة ويشغّلها من أول طلب إلى آخره.
- البيانات التجريبية تغطي حالة الاشتراك المنتهي وحالة جهتين مختلفتين.

```
اقرأ docs/PERSON_4.md.
نفّذ المهمة P4-02. تأكد من أنك داخل C:\Users\abdul\govagent-repo عبر
git rev-parse --show-toplevel قبل أي تعديل.
لا تعمل Commit أو Push أو Merge، ولا تنشئ فروعًا أو Issues.

المطلوب:
1. وسّع mock-data/: جهتان على الأقل، ولكل جهة مسؤول وعدة موظفين، بأدوار
   واشتراكات مختلفة — واحد ساري وواحد منتهٍ.
2. أضف محادثات وملفات تجريبية: أطوال مختلفة، ورسائل عربية واقعية، وأسماء
   وأنواع ملفات مختلفة.
3. ممنوع أي سر حقيقي أو بيانات حكومية حقيقية. كلمات المرور التجريبية تُذكر
   في التوثيق فقط، ولا تُخزَّن كنص صريح في أي مكان آخر.
4. أنشئ مجموعة Postman تغطي: /health، تسجيل الدخول، المحادثات، الرسائل، رفع
   الملفات، ومسارات لوحة المسؤول.
5. استخدم متغيرات base_url و token في المجموعة، واجعل طلب الدخول يملأ الـToken
   تلقائيًا حتى تعمل بقية الطلبات بلا تعديل يدوي.

في النهاية اذكر الملفات المضافة والمعدّلة، وما جرّبته فعليًا.
```

# P4-03 — حالات الاختبار الآلية

- **الحالة:** Not Started
- **تعتمد على:** عمل PERSON_1 و PERSON_2
- **الملفات المتوقعة:** `backend/tests/` · `docs/`

## ما تشمله

اختبارات `pytest` تغطي الحالات الحرجة:

1. **صحة الخدمة والمحادثة:** `/health` يعيد `ok`، و`/api/chat` يعمل بـ`mock`،
   والرسالة الفارغة تُرفض بـ422.
2. **المصادقة:** دخول صحيح، كلمة مرور خاطئة، مستخدم غير موجود، Token تالف،
   Token منتهٍ، ومسار محمي بلا Token.
3. **انتهاء الاشتراك:** جهة باشتراك منتهٍ تُمنع برسالة واضحة، وجهة سارية
   تعمل طبيعيًا.
4. **عزل الجهات:** مستخدم جهة (أ) لا يقرأ ولا يعدّل ولا يحذف أي محادثة أو
   ملف أو مستخدم من جهة (ب). **هذا أهم اختبار في الملف.**
5. **رفع الملفات:** امتداد مدعوم ينجح، وغير مدعوم يُرفض، والحجم الزائد
   يُرفض، والملف يُنسب للجهة الصحيحة.

**مهم:** الاختبارات **للتأكد والتسجيل فقط**، ولا تمنع حفظ العمل. سجّل الفشل
كما ظهر وأبلغ قائد الفريق. لا تعطّل اختبارًا لتمرير النتيجة.

## شرط الإنجاز

- كل الحالات أعلاه مكتوبة، وكل نتيجة مسجّلة كما ظهرت.
- الاختبارات التي تحتاج Oracle تُتخطّى بوضوح (`skip`) بدل أن تنهار.

```

لا تعمل Commit أو Push أو Merge، ولا تنشئ فروعًا أو Issues.

المطلوب: اكتب اختبارات pytest في backend/tests/ تغطي:
1. /health يعيد ok، و/api/chat يعمل بـmock، والرسالة الفارغة تُرفض بـ422.
2. المصادقة: دخول صحيح، كلمة مرور خاطئة، مستخدم غير موجود، Token تالف،

3. انتهاء الاشتراك: جهة باشتراك منتهٍ تُمنع برسالة واضحة، وجهة سارية تعمل.

الاختبارات للتأكد والتسجيل فقط. لا تعطّل أي اختبار فاشل ولا تخفِ أي فشل.

شغّل: cd backend && .venv/Scripts/python -m pytest
في النهاية اذكر الملفات المضافة ونتائج الاختبارات كاملة كما ظهرت فعلًا،
بما فيها الفاشلة والمتخطّاة.

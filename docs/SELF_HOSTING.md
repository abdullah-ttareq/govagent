# تشغيل GovAgent على سيرفر الجهة

دليل مختصر لتشغيل النظام داخل الجهة عبر Docker Compose.

النظام يعمل **بالكامل بلا قاعدة بيانات وبلا أي اشتراك خارجي** في وضعه
الافتراضي، فيمكن تجربته قبل تجهيز أي شيء.

---

## ١. المتطلبات

| المتطلب | ملاحظة |
|---|---|
| Docker و Docker Compose | على السيرفر. لا شيء غيرهما مطلوب. |
| منفذان مفتوحان: `3000` و `8000` | الواجهة والـBackend. |
| قاعدة Oracle | **اختيارية**، وخارج هذه المنظومة تمامًا. |
| اشتراك OCI Generative AI | **اختياري**، للردود الحقيقية بدل التجريبية. |

قاعدة Oracle **ليست جزءًا من `docker-compose.yml` عمدًا**: الجهة تملك قاعدتها
وتديرها بنفسها، ولا يجوز أن تتحكم هذه المنظومة بدورة حياة بياناتها.

---

## ٢. التشغيل

```bash
cp .env.example .env
docker compose up --build
```

ثم افتح `http://localhost:3000` من متصفح الموظف.

هذا كل شيء. الوضع الافتراضي يعمل بلا Oracle وبلا OCI:

- `MODEL_PROVIDER=mock` — ردود تجريبية واضحة أنها تجريبية.
- `RETRIEVAL_PROVIDER=memory` — مقاطع الملفات داخل ذاكرة العملية.

للتحقق من الخدمة:

```bash
curl http://localhost:8000/health
```

## ٣. ماذا تضبط وماذا تترك فارغًا

انسخ `.env.example` إلى `.env` وعدّل ما تحتاجه فقط. **كل ما عداه يُترك فارغًا.**

### للتشغيل التجريبي — لا تضبط شيئًا

انسخ الملف كما هو وشغّل. هذا هو وضع العرض والتجربة.

### للتشغيل الحقيقي داخل الجهة

| المتغير | متى تضبطه | مثال |
|---|---|---|
| `FRONTEND_URL` | دائمًا عند النشر | `https://govagent.gov.sa` |
| `NEXT_PUBLIC_BACKEND_URL` | دائمًا عند النشر | `https://api.govagent.gov.sa` |
| `MODEL_PROVIDER` | لتفعيل الردود الحقيقية | `oracle` |
| `OCI_REGION` · `OCI_COMPARTMENT_ID` · `OCI_MODEL_ID` | مع `MODEL_PROVIDER=oracle` | من Console الخاص بـOCI |
| `ORACLE_DSN` · `ORACLE_USER` · `ORACLE_PASSWORD` | لتفعيل حفظ البيانات والبحث | `host:1521/service` |
| `RETRIEVAL_PROVIDER` | مع تفعيل Oracle | `oracle` |
| `EMBEDDING_PROVIDER` · `OCI_EMBEDDING_MODEL_ID` | للبحث المتجهي الحقيقي | `oracle` |

> ⚠️ `NEXT_PUBLIC_BACKEND_URL` هو العنوان كما يراه **متصفح الموظف**، لا كما
> تراه الحاوية. لذلك ليس `http://backend:8000`. وهو يُدمج في الواجهة **وقت
> البناء**، فتغييره يستلزم `docker compose up --build` لا مجرد إعادة تشغيل.

خطوات تجهيز قاعدة Oracle وتشغيل المخطط في
[`database/README.md`](../database/README.md).

---

## ٤. الأسرار

- **لا يوجد أي سر في المستودع.** `.env.example` بقيم فارغة، و`.env` مستثنى من
  Git ولا يدخل الصور (`.dockerignore`).
- هوية OCI (`~/.oci/config` ومفتاح الـAPI) تبقى على السيرفر خارج المستودع
  وخارج الصور، وتُمرَّر بربط مجلد عند الحاجة.
- كلمة مرور قاعدة البيانات في `.env` على السيرفر فقط.

---

## ٥. ما لم يُنفَّذ بعد

هذه نسخة أسبوع العمل، وليست إعداد إنتاج نهائيًا:

- **لم يُجرَّب `docker compose up` فعليًا** — لم تكن Docker مثبّتة على جهاز
  التطوير. بُنيت الواجهة محليًا بنجاح وتأكد أمر التشغيل، لكن بناء الصور
  وتشغيلها معًا يحتاج تجربة على سيرفر فيه Docker.
- **تكامل Oracle الحقيقي** — Pending Oracle Setup: لا توجد قاعدة ولا بيانات
  دخول بعد.
- الحاويات تعمل بمستخدم `root`، ولا يوجد `HEALTHCHECK` ولا حدود موارد ولا
  Reverse Proxy مع TLS. تُضاف عند تثبيت إعداد الإنتاج.
- **لا يوجد تسجيل دخول بعد** (مهمة BE-03)، ولذلك تصل `organization_id` من
  العميل مؤقتًا. **لا تنشر النظام على شبكة مفتوحة قبل إتمام المصادقة.**

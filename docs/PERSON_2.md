# P2-01 — الهيكل والمصادقة و JWT

- **الحالة:** Not Started
- **تعتمد على:** لا شيء
- **الملفات المتوقعة:** `backend/app/api/` · `backend/app/core/` ·
  `backend/app/schemas/` · `backend/app/services/` · `backend/requirements.txt`

## ما تشمله

1. ترتيب هيكل FastAPI: فصل الـRouters عن الخدمات، وتجميع الـRouters في
   `api_router` واحد، وتسمية واضحة للمسارات والوسوم.
2. **تجزئة كلمات المرور** بـ`bcrypt` (أو `argon2`): دالة تجزئة ودالة تحقق.
   **لا يُخزَّن النص الصريح أبدًا.**
3. مسارات المصادقة: `POST /api/auth/login` و `GET /api/auth/me`، وتسجيل خروج
   إن لزم.
4. **JWT:** إصدار Token عند تسجيل الدخول يحمل `user_id` و `organization_id`
   و `role`، ومدة صلاحية معقولة، وسر يُقرأ من متغير بيئة.
5. `Dependency` للتحقق من الـToken تُستخدم لحماية بقية المسارات، وترفض
   المنتهي والتالف برسالة عربية واضحة.

## شرط الإنجاز

- تسجيل دخول بمستخدم تجريبي يعيد Token صالحًا.
- مسار محمي بلا Token يعيد 401 برسالة واضحة.
- كلمة المرور غير موجودة كنص صريح في أي مكان.

```
اقرأ docs/PERSON_2.md.
نفّذ المهمة P2-01. تأكد من أنك داخل C:\Users\abdul\govagent-repo عبر
git rev-parse --show-toplevel قبل أي تعديل.
افحص backend/app/ كاملًا قبل التعديل. لا تعِد إنشاء المشروع.
لا تعمل Commit أو Push أو Merge، ولا تنشئ فروعًا أو Issues.

المطلوب:
1. رتّب هيكل FastAPI: افصل الـRouters عن الخدمات، وجمّعها في api_router واحد
   بأسماء ووسوم واضحة.
2. أضف تجزئة كلمات المرور بـbcrypt: دالة hash ودالة verify. لا تخزّن النص
   الصريح في أي مكان إطلاقًا.
3. أضف مسارات المصادقة: POST /api/auth/login و GET /api/auth/me.
4. أصدر JWT عند تسجيل الدخول يحمل user_id و organization_id و role، بمدة
   صلاحية معقولة وسر يُقرأ من متغير بيئة. أضف المتغير إلى .env.example بقيمة
   فارغة.
5. اكتب Dependency للتحقق من الـToken تُستخدم لحماية بقية المسارات، وترفض
   الـToken المنتهي أو التالف برسالة عربية واضحة و401.

شغّل: cd backend && .venv/Scripts/python -m pytest
في النهاية اذكر الملفات المعدّلة ونتائج الاختبارات كما ظهرت فعلًا.
```

# P2-02 — الجهات والمستخدمون وعزل البيانات

- **الحالة:** Not Started
- **تعتمد على:** P2-01
- **الملفات المتوقعة:** `backend/app/api/` · `backend/app/services/` ·
  `backend/app/schemas/` · `database/schema.sql`

## ما تشمله

1. `CRUD` الجهات (`organizations`): إنشاء، قراءة، تحديث.
2. `CRUD` المستخدمين (`users`) داخل الجهة، مع دور `admin` أو `employee`.
3. **عزل `organization_id`** — أهم جزء في هذه المهمة: كل استعلام قراءة أو
   كتابة يُقيَّد بجهة المستخدم المأخوذة من الـToken، لا من جسم الطلب.
4. صلاحيات الدور: مسؤول الجهة يدير موظفيه فقط، والموظف يرى نفسه فقط.
5. اختبار يثبت أن مستخدم جهة (أ) لا يستطيع قراءة أو تعديل أي سجل لجهة (ب).

## شرط الإنجاز

- محاولة الوصول إلى سجل جهة أخرى تعيد 403 أو 404، لا بيانات.
- `organization_id` لا يُقرأ من جسم الطلب في أي مسار.

# P2-03 — المحادثات والرسائل والملفات

- **الحالة:** Not Started
- **تعتمد على:** P2-02
- **الملفات المتوقعة:** `backend/app/api/` · `backend/app/services/` ·
  `backend/app/schemas/` · `database/schema.sql`

## ما تشمله

1. `CRUD` المحادثات: إنشاء، قائمة محادثات المستخدم، إعادة تسمية، حذف.
2. حفظ **الرسائل**: رسالة المستخدم ورد الإيجنت داخل المحادثة، بترتيب زمني
   صحيح، مع الترقيم (Pagination) عند القراءة.
3. ربط `/api/chat` بالحفظ: كل تبادل يُخزَّن في محادثته تلقائيًا، وتُعاد

   والمحادثة. التخزين على القرص أو مسار محلي بسيط.
5. حدود واضحة: حجم أقصى، وامتدادات مسموحة، ورسالة عربية واضحة عند التجاوز.

- **تعتمد على:** P2-02

  `backend/app/schemas/` · `database/schema.sql`

## ما تشمله

1. **الاشتراكات:** لكل جهة اشتراك بتاريخ بداية ونهاية وعدد تراخيص (مقاعد).
2. **فحص انتهاء الترخيص:** عند تسجيل الدخول وعند كل طلب محمي — الاشتراك
   المنتهي يمنع الاستخدام برسالة عربية واضحة، لا بخطأ عام.

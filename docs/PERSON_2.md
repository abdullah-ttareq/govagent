# PERSON_2 — Backend و Database

**عدد المهام: ٥**

## دور الشخص الثاني

مسؤول عن بناء الـBackend وقاعدة البيانات والمصادقة وإدارة المستخدمين والجهات والمحادثات والملفات والاشتراكات.

---

# P2-01 — الهيكل والمصادقة و JWT

### وش تسوي؟

تجهيز هيكل الـBackend وإضافة نظام تسجيل الدخول والمصادقة باستخدام JWT، مع حماية بيانات المستخدمين.

### الخطة

1. ترتيب هيكل FastAPI وفصل المسارات عن الخدمات.
2. إضافة تجزئة كلمات المرور بشكل آمن.
3. إنشاء تسجيل الدخول وحساب المستخدم.
4. إصدار JWT يحتوي على بيانات المستخدم والجهة والصلاحية.
5. حماية المسارات باستخدام التحقق من الـToken.
6. رفض الـTokens المنتهية أو غير الصحيحة.

---

# P2-02 — الجهات والمستخدمون وعزل البيانات

### وش تسوي؟

إدارة الجهات والمستخدمين داخل النظام، مع ضمان أن كل جهة تستطيع الوصول إلى بياناتها فقط.

### الخطة

1. إنشاء وإدارة الجهات.
2. إنشاء وإدارة المستخدمين داخل كل جهة.
3. تحديد أدوار المستخدمين مثل Admin وEmployee.
4. تطبيق عزل `organization_id` على جميع البيانات.
5. جعل مسؤول الجهة يدير موظفي جهته فقط.
6. جعل الموظف يصل إلى بياناته حسب صلاحياته.
7. التأكد من عدم إمكانية الوصول إلى بيانات جهة أخرى.

---

# P2-03 — المحادثات والرسائل والملفات

### وش تسوي؟

إدارة محادثات المستخدم ورسائله والملفات التي يرفعها، وربطها بالـBackend والـRAG.

### الخطة

1. إنشاء وإدارة المحادثات.
2. حفظ رسائل المستخدم وردود الـAgent بترتيب زمني.
3. استخدام المحادثات السابقة كسياق للذكاء الاصطناعي.
4. رفع الملفات وحفظ معلوماتها الأساسية.
5. تحديد أنواع الملفات والأحجام المسموحة.
6. ربط الملفات بالجهة والمستخدم والمحادثة.
7. تطبيق صلاحيات الوصول على المحادثات والملفات.
8. حماية مسارات تخزين الملفات.

---

# P2-04 — الاشتراكات والتراخيص وإعدادات المودل والسجلات

### وش تسوي؟

إدارة اشتراك كل جهة وعدد المستخدمين المسموح بهم، بالإضافة إلى إعدادات نموذج الذكاء الاصطناعي وتسجيل العمليات المهمة.

### الخطة

1. إنشاء اشتراك لكل جهة بتاريخ بداية ونهاية.
2. تحديد عدد التراخيص أو المقاعد المتاحة.
3. منع استخدام النظام عند انتهاء الاشتراك.
4. منع إضافة مستخدمين عند تجاوز عدد المقاعد.
5. إضافة إعدادات خاصة بنموذج الذكاء الاصطناعي لكل جهة.
6. تسجيل العمليات المهمة في Audit Logs.
7. توفير سجل للعمليات يمكن لمسؤول الجهة الاطلاع عليه.

---

# P2-05 — الأخطاء والتوثيق واختبارات الـBackend

### وش تسوي؟

توحيد طريقة التعامل مع الأخطاء وتوثيق الـAPI واختبار جميع أجزاء الـBackend.

### الخطة

1. إنشاء نظام موحد لرسائل الأخطاء.
2. عرض رسائل واضحة باللغة العربية للمستخدم.
3. منع ظهور المعلومات الداخلية أو Stack Trace للمستخدم.
4. توثيق جميع API في Swagger.
5. إضافة أمثلة للطلبات والردود.
6. إضافة دعم تسجيل الدخول باستخدام JWT داخل Swagger.
7. اختبار المصادقة والصلاحيات وعزل الجهات.
8. اختبار المحادثات والرسائل والملفات والاشتراكات.
9. اختبار النظام بالكامل والتأكد من تكامل أجزاء الـBackend.

# PERSON_1 — قائد الفريق · AI و RAG و Oracle والتكامل

**عدد المهام: ٦**

## دور الشخص الأول

مسؤول عن بناء وربط أهم أجزاء النظام المتعلقة بالذكاء الاصطناعي، RAG، Oracle، وتشغيل النظام وتكامله بشكل نهائي.

---

# P1-01 — طبقة مزود المودل

### وش تسوي؟

تجهيز طبقة الذكاء الاصطناعي التي يتعامل معها النظام، بحيث تدعم المحادثة وسياق الرسائل، وتربط النظام بنموذج الذكاء الاصطناعي.

### الخطة

1. دعم سياق المحادثة والرسائل السابقة.
2. تجهيز مزود للنموذج يدعم Oracle OCI Generative AI.
3. إعداد شخصية المساعد كمساعد حكومي باللغة العربية.
4. التعامل مع أخطاء الاتصال والإعدادات.
5. التأكد من أن النظام يستطيع العمل بالمزود المحلي أثناء التطوير.

---

# P1-02 — Oracle وقاعدة البيانات

### وش تسوي؟

تجهيز الاتصال بقاعدة بيانات Oracle وإنشاء البنية التي يحتاجها النظام لتخزين البيانات والملفات والمعلومات الخاصة بالبحث.

### الخطة

1. إنشاء طبقة اتصال بقاعدة Oracle.
2. تجهيز Connection Pool لإدارة الاتصالات.
3. إنشاء وتشغيل مخطط قاعدة البيانات.
4. تجهيز الجداول والعلاقات والفهارس المطلوبة.
5. إضافة حالة اتصال Oracle ضمن فحص النظام.
6. توثيق طريقة إعداد قاعدة البيانات وتشغيلها.

---

# P1-03 — استخراج الملفات والتقطيع

### وش تسوي؟

تحويل الملفات التي يرفعها المستخدم إلى نص قابل للمعالجة والبحث، ثم تقسيم النص إلى أجزاء صغيرة وتجهيزها للـRAG.

### الخطة

1. دعم ملفات PDF وDOCX وTXT.
2. استخراج النص من الملفات.
3. رفض الملفات غير المدعومة.
4. تقسيم النص إلى Chunks مع الحفاظ على الفقرات قدر الإمكان.
5. ربط كل Chunk بالملف والجهة التابعة له.
6. إنشاء Embeddings لكل جزء.
7. تخزين البيانات استعدادًا للبحث المتجهي.

---

# P1-04 — RAG والبحث المتجهي

### وش تسوي؟

تمكين النظام من البحث داخل ملفات الجهة والعثور على المعلومات المرتبطة بسؤال المستخدم، ثم استخدامها لإنتاج إجابة مناسبة مع إظهار مصادرها.

### الخطة

1. تنفيذ البحث المتجهي داخل قاعدة البيانات.
2. البحث عن أكثر أجزاء الملفات ارتباطًا بالسؤال.
3. ضمان أن المستخدم يرى بيانات جهته فقط.
4. تمرير المعلومات المسترجعة إلى نموذج الذكاء الاصطناعي.
5. ربط RAG بالمحادثة.
6. إظهار مصادر الإجابة مثل اسم الملف ورقم الجزء.
7. السماح للمساعد بالإجابة من معرفته العامة عند عدم وجود ملفات مناسبة.

---

# P1-05 — تشغيل النظام والإعداد

### وش تسوي؟

تجهيز النظام ليكون سهل التشغيل والنشر، بحيث تعمل الواجهة والـBackend معًا ويمكن إعداد النظام على سيرفر الجهة.

### الخطة

1. تجهيز Docker للـBackend.
2. تجهيز Docker للـFrontend.
3. إنشاء Docker Compose لتشغيل الخدمات معًا.
4. ربط إعدادات النظام بمتغيرات البيئة.
5. إبقاء قاعدة Oracle خارج النظام باعتبارها قاعدة تابعة للجهة.
6. تجهيز إعدادات التشغيل والنشر.
7. توثيق متطلبات تشغيل النظام.

---

# P1-06 — التكامل والاختبار النهائي

### وش تسوي؟

دمج جميع أجزاء المشروع والتأكد من أن النظام يعمل كمنظومة واحدة من تسجيل الدخول وحتى الحصول على إجابة من الـAgent.

### الخطة

1. دمج أعمال أعضاء الفريق الأربعة.
2. ربط Backend وFrontend والإضافة.
3. اختبار رحلة المستخدم كاملة.
4. اختبار المحادثة ورفع الملفات وRAG والمصادر.
5. التأكد من عزل بيانات الجهات.
6. مراجعة الجوانب الأمنية.
7. اختبار النظام بالكامل.
8. تحديد أفضل خيار للاستضافة.
9. إعداد التقرير النهائي بما تم إنجازه والمشاكل المتبقية.

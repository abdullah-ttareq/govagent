# بيانات تجريبية

بيانات خيالية بالكامل للتطوير والاختبار المحلي. **لا تُستخدم في أي بيئة حقيقية،
ولا تُضاف إليها بيانات حكومية أو شخصية حقيقية.**

## المحتوى الحالي

- `organizations.json` — ثلاث جهات تجريبية بمستخدميها واشتراكاتها.
  - `digital-services` — اشتراك **فعّال**، ١٠ مقاعد.
  - `urban-planning` — اشتراك **فعّال**، ٥ مقاعد، وفيه حساب معطّل عمدًا.
  - `national-archive` — اشتراك **منتهٍ** عمدًا، لاختبار منع الطلبات (QA-06).

**الجهتان الأوليان معًا** تُستخدمان لاختبار عزل البيانات بـ`organization_id`
(QA-07)، ولذلك يجب أن تبقى **كلتاهما فعّالة**: جهة لا يُسجَّل الدخول إليها لا
تصلح طرفًا في إثبات العزل. ولذلك أُفردت جهة ثالثة لحالة الانتهاء، فتُختبر
الحالتان معًا بلا تعارض.

## كلمات المرور

الملف لا يحتوي كلمات مرور. عند تحميل هذه البيانات في قاعدة البيانات، تُولَّد
كلمة مرور موحّدة للتطوير المحلي وتُخزَّن **مُجزّأة** فقط.

كلمة مرور التطوير المتفق عليها تُحدَّد في مهمة QA-01 وتُوثَّق هنا. هي للتطوير
المحلي فقط ولا تُستخدم في أي نشر حقيقي.

مؤقتًا (منذ P2-01): مخزن الذاكرة `DATA_STORE=memory` يزرع هؤلاء المستخدمين
بكلمة مرور واحدة هي قيمة `DEV_SEED_PASSWORD` في `.env` — افتراضها
`GovAgent@2026`. عند تثبيت كلمة المرور في QA-01 يكفي تغيير هذا المتغير بلا
تعديل كود.

## الاشتراكات في مخزن الذاكرة

**مخزن الذاكرة يزرع الحالات نفسها حرفيًا** — الحالة والمقاعد والتواريخ:

| الجهة               | الحالة   | المقاعد | الانتهاء   |
| ------------------- | -------- | ------- | ---------- |
| `digital-services`  | active   | ١٠      | 2030-01-01 |
| `urban-planning`    | active   | ٥       | 2030-01-01 |
| `national-archive`  | expired  | ٥       | 2025-06-30 |

لا انحراف بين هذا الملف والمخزن. عند تعديل حالة هنا يجب تعديلها في
`backend/app/services/organization_settings_store.py` و
`backend/app/services/user_store.py` — التطابق يدوي لأن صورة الـDocker
تنسخ `backend/app` فقط ولا تصل إلى هذا الملف.

يحرس التطابقَ اختبارٌ في `backend/tests/test_subscriptions.py` يفشل إن
توقفت جهة فعّالة عن كونها كذلك، أو إن تغيّر تاريخ الجهة المنتهية.

# GovMind — إضافة المتصفح

نافذة عربية RTL **لتجهيز GovMind على جهازك**: دخول، فحص اشتراك، تفعيل
الجهاز، تنزيل المثبّت.

**Manifest V3 · HTML + CSS + JavaScript مباشر · بلا React وبلا Build System.**

---

## ⚠️ لم تعد هذه الإضافة واجهة محادثة

الإصدار السابق (0.2.x) كان نافذة محادثة مع حقل «رابط السيرفر» في الإعدادات.
**أُزيل ذلك كله** مع تحوّل GovMind إلى منتج باشتراك يُثبَّت على الجهاز:

| ما كان | ما صار |
|---|---|
| محادثة داخل النافذة | ✂️ حُذفت — GovMind يعمل على الجهاز لا في المتصفح |
| حقل «رابط السيرفر» في الإعدادات | ✂️ حُذف — العنوان ثابت في `config.js` وقت البناء |
| `optional_host_permissions` لكل النطاقات | ✂️ حُذفت — نطاق واحد معلن |
| مفتاح `apiBaseUrl` في التخزين | ✂️ يُمسح تلقائيًا عند أول تشغيل بعد التحديث |

## ما تفعله وما لا تفعله

تفعل:

- **تسجيل الدخول** عبر `POST /api/account/login` (‏Supabase Auth خلف الـBackend).
- **قراءة حالة الاشتراك** وعرضها: فترة تجريبية، فعّال، منتهٍ، موقوف، ملغى.
- **تفعيل هذا الجهاز** — كل اشتراك يعمل على **جهاز واحد**.
- **تنزيل المثبّت** عبر `chrome.downloads` مع نسبة وحجم وإلغاء ومعالجة فشل.
- **إرشاد المستخدم** إلى فتح الملف والموافقة على نافذة ويندوز.
- **وضع فاتح وداكن وتلقائي** — ثلاثة خيارات، في الإضافة وحدها.

لا تفعل:

- ❌ **لا محادثة** ولا إرسال أي نصّ إلى مودل.
- ❌ **لا `content_scripts`** — صفر، ويثبته `manifest.json`.
- ❌ **لا تقرأ أي صفحة** ولا تطلب صلاحية لذلك (لا `activeTab` ولا `tabs`
  ولا `scripting`).
- ❌ **لا تطلب من المستخدم رابطًا ولا عنوان سيرفر ولا مفتاح API.**
- ❌ **لا تعرض رابط Azure** ولا تسمح بنسخه.
- ❌ **لا تشغّل ملف `.exe` تلقائيًا.** لا يوجد في الشيفرة استدعاء يفعل ذلك.
  فتح المثبّت فعل المستخدم وحده.
- ❌ **لا تنادي Supabase ولا Azure مباشرة**؛ كل شيء عبر الـBackend.

### الصلاحيات

| الصلاحية | السبب |
|---|---|
| `storage` | حفظ رمز الدخول وبصمة الجهاز وعلامة الترحيب. |
| `downloads` | تنزيل المثبّت وقراءة تقدّمه وإلغاؤه وإظهاره في المجلد. |
| `host_permissions` لعنوان الـBackend وحده | إرسال الطلبات إليه. |

> **رمز الدخول في `chrome.storage.local`.** تخزين الإضافة معزول عن كل صفحة،
> ولا تقرأ الإضافة أي صفحة أصلًا ولا تملك صلاحية لذلك.

## الشاشات التسع

```
١) ترحيب  →  ٢) دخول  →  ٣) تفعيل الجهاز  →  ٤) تثبيت  →  ٥) اكتمل
                              ↓ (حالات مانعة، خارج المسار)
              حساب بلا جهة · اشتراك منتهٍ/موقوف/ملغى · مفعّل على جهاز آخر
                                       ↓
                            جارٍ التنزيل (بين ٤ و٥)
```

**القرار في مكان واحد:** `lib/steps.js` دالة نقية `resolveStep(state)` تقول
أي شاشة تُعرض، و`popup.js` يعرض ما تقوله. لا شرط تدفّق مكرَّر في معالِج حدث.

## التشغيل

1. شغّل الـBackend على العنوان المذكور في `config.js`.
2. `chrome://extensions` ← **Developer mode** ← **Load unpacked** ← اختر
   مجلد `extension/`.

### تغيير عنوان الـBackend قبل التوزيع

**قيمتان تُغيَّران معًا أو لا تُغيَّر أيٌّ منهما:**

1. `BACKEND_URL` في `config.js`.
2. `host_permissions` في `manifest.json`.

اختلافهما يجعل المتصفح يرفض كل طلب بلا رسالة مفهومة.

## بصمة الجهاز

معرّف **عشوائي** يُولَّد مرة واحدة ويُحفظ في `chrome.storage.local` — لا
«بصمة» مستنتَجة من `userAgent` والشاشة والخطوط. الاستنتاج أسلوب تتبّع، وهو
هنا أسوأ وظيفيًا كذلك: يتغيّر مع كل تحديث للمتصفح فيفقد المستخدم تفعيله بلا
سبب مفهوم.

⚠️ **البصمة تُجزَّأ على السيرفر ولا تُخزَّن خامًا في القاعدة أبدًا**
(HMAC-SHA256 بمِلح سرّي — انظر `backend/app/core/device_id.py`).

**حدّه المعروف:** إعادة تثبيت الإضافة أو ملف تعريف Chrome آخر يولّد معرّفًا
جديدًا على الجهاز نفسه، فيحتاج المستخدم إبطالًا من المسؤول. الربط بعتاد
الجهاز يأتي مع GovMind Runtime في المرحلة التالية.

## الاختبارات

```bash
cd extension
npm install
npm test
```

٨٧ اختبارًا تغطي **الشاشات التسع كلها** عبر DOM حقيقي (jsdom) و`fetch`
مزيّف و`chrome` مزيّف يحاكي السلوك لا الشكل: التخزين قاموس حقيقي،
والتنزيلات سجلٌّ بحالة تتغيّر. `popup.html` تُقرأ من القرص لا تُكتب في
الاختبار — اختبارٌ على نسخة يدوية يمرّ بينما الصفحة الحقيقية مكسورة.
